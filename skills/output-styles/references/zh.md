# Chinese Reply Patterns

Read this when the reply is in Chinese. The body of `output-styles` owns the method; this reference supplies the counting rule, the common filler patterns, the contrast rewrite, and the typesetting conventions for Chinese replies.

## 句长计数

- 一个汉字计 1；一个英文单词、数字或代码标识符计 1；标点计 0。
- 步骤句最多 30；描述句最多 40。超过时拆成两句，或把并列项改成列表。

## 虚化动词与包装语

把动作写成动词本身。左列是常见的包装写法，右列是直接写法。

| 包装写法 | 直接写法 |
| --- | --- |
| 对 X 进行修改 / 处理 / 检查 | 修改 / 处理 / 检查 X |
| 予以 X、加以 X、进行 X | X |
| 做好 X 工作、完成 X 的操作 | X |
| 实现 X 功能 | 增加 X，或写出 X 的具体行为 |
| 作出 X 决定 | 决定 X |
| 通过 X 的方式 | 用 X |
| 存在 X 问题 | 写出具体现象 |
| 有一定的 X | 写出具体的量；没有量时删除 |
| 将会 X | 会 X |
| 值得注意的是 / 需要指出的是 / 总的来说 | 删除引导语，直接写内容 |

「处理」本身也是包装词；能写出具体动作时用具体动作。

## 术语与黑话

- 用户或项目已有的词优先：选了「卡」就一直用「卡」。
- 用现成的词和短语；四个以上名词连写时拆开：「终端会话失败时的界面状态」。
- 列举写全，或写出完整清单的位置。
- 同一强度用同一个情态词：要求用「必须」，禁止用「不得」，允许用「可以」。引用来源原文时保留原词并加引号。

## 句式

- 动作者明确时用主动句：「刷新请求使旧 token 失效」。
- 主语省略后有两种读法时补出主语。
- 条件在前：「连接失败时，显示错误」。
- 用肯定句表达要求：「必须确认」。
- 长「的」字链拆句：「仓库里负责渲染全局指令的模板」。

## 对比与否定

陈述事物是什么，让断言靠依据成立。只有当用户或证据显示存在某种误读时，才在正向句之后补一句它不是什么，每个话题至多一处。「这不等于 / 不代表 / 更不是」连环句拆回各自的正向断言，或整段删除。

| 改前 | 改后 |
| --- | --- |
| 当前开关不是「全网络禁止 ICMP」。它只拒绝进入 sing-box、且没有被前面的 Direct 规则放行的匹配流量。被 TUN 排除的地址不受这个 reject 控制。 | `icmp_reject` 只拒绝已进入 sing-box、未被前置 Direct 规则放行的 ICMP echo；TUN 排除的地址绕过它。 |
| 这个检查不是只看进程，这是优点。它检查 unit、API、TUN，再做 DNS 和 HTTPS 204。 | 这个检查覆盖 unit、API、TUN，再做 DNS 和 HTTPS 204。 |
| HA 健康不等于每个业务都正常，也不代表 Internet 可达，更不能证明代理链路健康。 | HA 健康只证明顶层 `Proxy` 路径可用；各业务 selector 的可用性另行探测。 |

## 不确定性

- 未确认的事实写「未确认」并给出确认方法。
- 「可能」只用于有依据的概率判断，并写出依据：「缓存可能是原因，因为只有 EU 节点设置了 `CACHE_TTL=900`」。
- 未运行的检查和原因合并写在结尾一行。

## 标点与混排

- 中文正文用全角标点「，。；：（）」；强调或引用界面文案用直角引号「」。
- 代码、命令、路径、标识符写在反引号内，内部保持半角。
- 中文与英文单词、数字之间加一个半角空格；中文与全角标点之间紧邻。
