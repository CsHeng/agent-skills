# Chinese Reply Patterns

Read this when the reply is in Chinese. The body of `output-styles` owns the method; this reference supplies the counting rule, the common filler patterns, and the typesetting conventions for Chinese replies.

## 句长计数

- 一个汉字计 1；一个英文单词、数字或代码标识符计 1；标点不计。
- 步骤句不超过 30；描述句不超过 40。超过时拆成两句，或把并列项改成列表。

## 虚化动词与包装语

把动作写成动词本身。左列是常见的包装写法，右列是直接写法。

| 包装写法 | 直接写法 |
| --- | --- |
| 对 X 进行修改 / 处理 / 检查 | 修改 / 处理 / 检查 X |
| 予以 X、加以 X、进行 X | X |
| 做好 X 工作、完成 X 的操作 | X |
| 实现 X 功能 | 增加 X，或写出 X 的具体行为 |
| 作出 X 决定 | 决定 X |
| 通过 X 的方式 | 用 X |
| 存在 X 问题 | 写出具体现象 |
| 有一定的 X | 写出具体的量；没有量时删除 |
| 将会 X | 会 X |

「处理」本身也是包装词；能写出具体动作时不用它。「值得注意的是」「需要指出的是」「总的来说」这类引导语删除，直接写内容。

## 术语与黑话

- 用户或项目已有的词优先：选了「卡」就不再写「任务」「工单」「ticket」。
- 不自创缩写和复合名词。四个以上名词连写时拆开：「终端会话失败时的界面状态」，不写「终端会话失败反馈界面状态」。
- 列举写全，或写出完整清单的位置；不用「等」「之类」收尾。
- 同一强度用同一个情态词：要求用「必须」，禁止用「不得」，允许用「可以」。引用来源原文时保留原词并加引号。

## 句式

- 动作者明确时不用「被」字句：「刷新请求使旧 token 失效」，不写「旧 token 被刷新请求失效」。
- 主语省略后有两种读法时补出主语。
- 条件在前：「连接失败时，显示错误」，不写「显示错误，如果连接失败的话」。
- 不用双重否定：「必须确认」，不写「不能不确认」。
- 长「的」字链拆句：「仓库里负责渲染全局指令的模板」比「仓库的负责全局指令的渲染的模板」清楚。

## 不确定性

- 未确认的事实写「未确认」并给出确认方法；不用「可能」「大概」「应该是」代替。
- 「可能」只用于有依据的概率判断，并写出依据：「缓存可能是原因，因为只有 EU 节点设置了 `CACHE_TTL=900`」。

## 标点与混排

- 中文正文用全角标点「，。；：（）」；强调或引用界面文案用直角引号「」。
- 代码、命令、路径、标识符写在反引号内，内部保持半角。
- 中文与英文单词、数字之间加一个半角空格；中文与全角标点之间不加空格。
