# Full Project Truth Audit

Use this reference when the user requests comprehensive project orientation or a full truth audit; a local question or incomplete documentation needs deeper investigation of one gap only.

## Audit Concerns

Choose the concerns relevant to the requested audit and cover them once. Present these information responsibilities in an order and structure suited to the answer:

- Project purpose, scope, current conclusion and the facts that define it.
- Stable truth roots, stage artifact roots, root reference files, document health and verification basis (labels in [Document Health And Drift](doc-health-and-drift.md)).
- Repository-local terminology that affects architecture, operation, lifecycle, compatibility or status.
- Search boundaries, controlling ignore files and any explicit historical or generated search path used, including whether historical stage material influenced the answer.
- Ownership, dependency direction, control/data paths and other relevant architecture boundaries.
- Validated entrypoints, commands and operating conditions.
- Implemented, in-progress, planned, unverified and out-of-scope work that materially affects current state.
- Actual gaps or drift, reported per Drift Signals in [Output Contract](output-contract.md).

Name the analyzed scope and give stable truth roots and root reference files with precise source references. Combine related concerns or omit inapplicable sections; when missing evidence affects a requested conclusion, state the gap. Keep each finding understandable with the evidence needed to verify it, and let related facts share a compact paragraph, list or table.
