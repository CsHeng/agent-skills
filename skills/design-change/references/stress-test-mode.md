# Stress-Test Mode

Use this reference only when the user explicitly asks to grill, stress-test, harden, challenge, or interrogate a design or plan.

## Challenge The Decision

Investigate the facts before asking questions. Focus on choices that change the outcome, operating or maintenance burden, ownership, data path, acceptance, recovery, or authority. Examine whether proposed safeguards and compatibility obligations are necessary as well as whether protections are missing.

Ask independent decision-changing questions together when that helps the user compare them. Defer a dependent question until its prerequisite is settled, and honor a request to proceed one question at a time. Give each question enough context, a recommendation, and the meaningful tradeoff. Use short labels if answers need to refer back; fixed identifiers and a separate frontier ledger are unnecessary.

After each reply, update the unresolved decisions. Revisit settled choices when new evidence warrants it, and focus the interrogation on relevant design branches. Facts that tools can establish and local choices already delegated to the executor remain agent work.

## Finish With A Usable Decision

Fold the supported decisions and reasons into the design or plan, including any changed acceptance or authority boundary. Use a diagram where it can replace repetitive explanation of alternatives or dependencies.

Finish when no material decision-changing question remains. Continue within existing authority, or state the specific approval still needed before the affected action. Implementation and delivery require their own covered authority; proceed on explicit decisions within existing authority.
