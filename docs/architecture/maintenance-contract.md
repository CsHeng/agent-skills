# Maintenance Contract

`src/skills/` is authored truth. `contracts/skills.toml` owns the 39 public IDs, source mapping, activation mode, distribution, default role, mutation guards, and real semantic dependencies. Distributed skills are projected into `skills/`; undistributed public IDs remain contracted and authored but are omitted from that payload. The installed routing contract owns trigger cases, support routes, and response composition; it has no phase, mode, or gate authority.

Generators produce `skills/`, `skills.index.json`, and architecture diagrams. Static checks validate parseability, inventory, discovery metadata, reference closure, generated parity, documentation, lint, types, and tests. They do not validate workflow artifacts, enforce a lifecycle, or execute agent behavior.

Instruction changes use bounded semantic review and appropriate prose, link, and distribution checks. Goal-and-risk counterexamples under `testing-strategy` support offline review and optional controlled comparisons; they are not runtime rules or mandatory live-model trials. Passing maintenance checks does not establish fewer interruptions, lower cost, or safer agent behavior. Effective plans retain current goals, discretion, and boundaries while superseded execution history stays in stage records.

`skill-miner` also reads native Pi v3 session JSONL, with explicit recorded-branch selection, incomplete/fork evidence limitations, separate stop/model observations, and categorical rather than raw Pi text samples. These are candidate mining signals, not automatic judgments of task success or premature stopping. Its synthetic CLI regression suite lives under `src/skills/disciplines/skill-miner/tests/`; run it explicitly because root pytest discovery does not include nested Skill tests. Parsing needs no Pi runtime, user histories, credentials, or model experiment.
