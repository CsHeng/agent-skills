# Skill Composition

This product provides portable semantic capabilities, not an agent loop or orchestration runtime. Its methods work independently of Pi and of any architecture checkout.

## Product Contract

- Directly matched Skills do not require a router. `use-coding-skills` is an optional route for ambiguous requests and session-boundary work.
- The active agent chooses one primary response owner and useful overlays; `output-styles` composes as a rendering baseline, not a competing intent. Installed routing guidance declares real semantic dependencies, not fixed phases or executable transitions.
- Review is conditional on explicit intent, applicable policy or evidence-backed risk. Standalone review needs its bounded target, not reconstructed lifecycle artifacts. Evaluators are read-only; the calling agent judges findings and authorizes repair.
- Skills preserve task authority and protected behavior. They do not grant publication, deployment, commit, push, installation or destructive mutation. Current project records may have an explicitly declared external owner; summaries are recall, not new authority.
- Bounded implementation and verification labor may be delegated when the host permits it. A writable child owns one repository; the main agent integrates cross-repository work and keeps acceptance. No Skill depends on a specific host tool, scheduler, route or persistent ledger.
- An implementation follows the authorized main goal through verified delivery. Secondary discretion must already be authorized; a failed check or unavailable helper is not permission to lower acceptance. Ordinary diagnosis and in-scope repair do not require restarting design.
- Product validation covers inventory, discovery, reference closure, generated parity and ordinary code quality. Passing static checks does not establish live-model effectiveness or reduced cost.
