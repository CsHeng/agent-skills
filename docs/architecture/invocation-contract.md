# Invocation Contract

Skill frontmatter descriptions are the primary discovery surface. They expose the decision a Skill resolves and the important direct-execution exclusions; callers need not load the router to discover those exclusions. An explicitly named or confidently matched Skill runs directly; `use-coding-skills` is optional guidance for genuine selection ambiguity or session-boundary needs. A bounded implementation or routine test under an established strategy does not enter design, planning, or oracle selection merely because of phase terminology.

One primary Skill owns the response. Session, discipline, policy, tool, and review-component Skills may contribute bounded overlays. The active coding agent owns ordering, evidence judgment, conditional review, adjudication, and the final response; Skill categories do not grant lifecycle authority.

Standalone review accepts one bounded target and never creates missing design, plan, or implementation work. Review evaluators are optional, read-only helpers discovered by their own descriptions. The active caller adjudicates and authorizes accepted repair and decides whether changed evidence warrants targeted rereview; authorized workers may execute local checks and repairs, but evaluators remain read-only; each evaluation is bounded, but there is no default whole-change repair count. Neither review success nor artifact maintenance grants user approval to alter the acceptance baseline or proceed beyond the authorized request.

A delegated brief preserves the parent objective, protected behavior, important rationale, readable inputs, allowed writes, and completion evidence without requiring the original conversation. Scope-contained dispatch refinement is not a new design approval. Same-task follow-up prefers a valid original executor where supported, supplies current candidate and incremental evidence, and retains prior decisions while their evidence holds. Host capability, permissions, and current state govern continuation; session reuse never converts a worker into an independent reviewer or a stale summary into accepted truth. None of these methods requires the optional router, a permanent task ledger, or host-specific plan fields.

Discoverable facts and execution products such as bindings, digests, and verification receipts belong to agent investigation and execution, not new human prerequisites. Once clarification resolves the actual blocker, resume the original authorized task rather than ending on an acknowledgment. Briefs preserve main goals, authorized secondary discretion, relevant environment facts, and real pause conditions; they do not create operational permission or require exhaustive implementation detail.

A plan intended for later implementation ends with a user-facing approval summary that distinguishes (1) the actions, targets, repositories, and side effects the user may approve together, (2) already covered authority, (3) technical checks, investigable facts, and generatable products the agent must execute rather than ask approval for, and (4) remaining real manual checkpoints and pause conditions. This makes prospective implementation approval actionable without granting it, does not force plan-only work to request implementation authority, and prevents ordinary in-scope execution from becoming serial user approval prompts.

Design and planning name the useful delivery endpoint for the kind of work without granting operational permission. Applications and services consider commit, push, existing-environment deploy, and post-deploy verification; libraries, tools, and Skills use the relevant publish, install, or handoff endpoint. A plan-only current request may still propose those future endpoints; an explicit source-only or design-only scope stays inside that request. Later explicit additions such as commit, push, or deploy update the currently effective plan and summary when authorized; they do not stack contradictory live gates, rewrite unrelated constraints, treat review or document annotation as authority, or waive verification. These are scope-specific continuation rules, not a universal execution engine or approval ledger.
