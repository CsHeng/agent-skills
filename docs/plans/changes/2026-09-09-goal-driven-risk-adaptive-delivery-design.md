# 目标驱动、风险适配与执行裁量设计

日期：2026-09-09。源码基线：`024312cbb1007c3578d5257d03301e184f041bf9`。

状态：用户已确认方向、批准本地实施；本设计对应的源码、验证与真相同步已完成，证据与限制见配套计划。审查本身不产生额外操作权限。配套入口：[实施计划](2026-09-09-goal-driven-risk-adaptive-delivery-plan.md)。源码维持英文，阶段文档使用中文。

## A. 目标与交付边界

本变更使共享 Skills 按主目标、已授权裁量空间和实际风险推进，而不是把每条计划文字、技术未知或安全建议都当作人工审批条件。设计保护结果和重要边界，实施者负责局部技术判断；连续推进和防止越界是同时需要满足的目标。

本仓库的交付包括三部分：工作流及其 overlays 的一致语义；精简的计划/收尾表达与正反行为场景；现有 `skill-miner` 的 Pi JSONL 只读输入支持。三部分都是本里程碑成果，不能因为后两项支持主目标就默认为可省略。真实模型下减少中断、时间或成本的效果属于后续测量，不是本次未经执行即可宣称的结果。

保持 39 public IDs、直接匹配绕过 router、reviewer 只读、parent 裁决、当前 checkout 默认及 authored/generated parity。不新增 Skill、工作流引擎、审批协议、风险评分表、运行时状态、自动续跑 hook 或模型特定分支。

不修改 Pi Extensions、全局 AGENTS、安装配置或 Drone/Homelab 的代码、计划和运行环境。不重新选择 Go/Python 项目的库，不扩大成全仓安全、测试或历史文档清理。开发环境可重建与生产风险差异是通用判断方法；某项目的具体用途、可丢弃数据和部署权限仍由该项目持有，本设计不授予任何外部删除或部署权限。

## C. 已确认的语义决定

### C1. 目标优先级与硬边界分开

主目标、其必要条件、用户明确固定的技术选型和适用的不可破坏边界必须兑现。best-effort 次要目标允许实施期依据证据替代、降级或舍弃，并继续主目标。设计记录这项裁量及边界即可，不必逐项列出所有可能失败的 feature；不能反过来要求设计调研到实现深度。

裁量来源是当前请求、批准设计或适用项目约定，不是 agent 为了得到通过而事后自授。明确要求的成果不能自行降格；名为次要的能力若事实上是主目标的必要依赖，也不能舍弃后冒称主目标完成。普通 bug、一次失败或未知可行性不自动等于不可支持；获得足以解释取舍的调查/试验依据即可，不要求穷尽一切方案。

用户指定“使用某库完成某目标”时，库选择是边界；库之间的 glue、辅助结构和局部算法由实施者决定。没有授权替代空间时，不因个人偏好更换指定库，也不要求用户设计每段 glue。

### C2. 风险不是自动停止条件

结合实际暴露、可利用性、预期损失、状态价值、影响范围、恢复成本与控制成本，选择足以支撑当前目标的措施。无需评分系统、零风险证明或固定控制清单。安全相关性触发判断，不自动把建议提升为必做项；明显可利用且后果严重的问题不能仅凭“开发”标签放行。

| 当前执行目标 | 默认策略 | 仍须保护的边界 |
| --- | --- | --- |
| 已授权、可重建的开发环境 | 可破坏性更新、重建、替换部署，优先 fix-forward；主路径、相关回归和冒烟 | 不越过批准的目标/状态范围，不波及生产、共享宿主或真实秘密 |
| 开发环境内需保留的状态 | 保护相关部分，必要时针对性备份/导出 | 唯一数据、凭据和明确保留对象，不把例外升级成整包生产流程 |
| 实际生产环境，尤其破坏性变更 | 明确目标、影响、授权及必要恢复方案，按变更验证恢复能力 | 真实服务、重要数据、访问和外部行为承诺 |

远端主机、多仓库、Ansible 和 deploy 字样不等于生产。环境和权限优先使用已有可信项目事实；目标不明时做最小必要核实，不建设盘点系统或每次重新询问。尚存明确项目约束冲突时，不能靠本通用 Skill 绕过；只提出受影响的具体冲突。

### C3. 连续执行与局部暂停

批准范围内的事实调查、绑定/digest/回执生成、实现选择、验证与修复由 agent 完成。用户回答解决阻塞后，恢复原已授权任务，不只输出确认或未来行动承诺再等待“继续”。本地技术困难优先诊断或在裁量内取舍，不自动重启 design/plan。

best-effort 差异在既有交付范围和风险预期内时，可以继续已授权的开发或生产部署。若它改变主目标，或使后续生产动作的承诺、风险、目标或权限超出批准边界，在该影响发生前取得新的窄授权。暂停受影响的动作，独立、安全、已授权工作继续；不能上线后才披露需重新接受的风险。凭据、工具能力和 review 通过都不产生操作权限。

### C4. 验证保护用户结果，且按变化复用

选择能证明主目标和重要边界的最小现实证据，不以数量、全矩阵或形式严格程度衡量质量。用户体验目标须有对应场景，例如不同业务独立选点、首次初始化来源、指定版本启动告警；parser/存在性/golden 不替代这些行为。

授权的次要能力取舍属于验收允许的结果，不是删断言来掩盖失败。记录适配结果及证据，保留主目标和硬边界的独立 oracle；已有测试与授权裁量冲突时据独立契约修正、按实际风险审查，不能自行改写必达要求。

恢复验证由变更触及的状态和旧证据是否失效决定，不由提交、修复次数或 candidate digest 改变决定。模板变化不自动触发数据库还原演练；数据格式、迁移、恢复实现或运行条件改变时，重验受影响的路径。生产备份刷新不等于重做全部恢复证明。已授权可丢弃开发状态可用重建恢复，不强求原地升级/向后兼容；需保留的既有数据仍须相应迁移验证。调整重跑范围不等于跳过适用仓库明确要求的检查。

### C5. 条件化安全建议，不新建加固项目

保留凭据保护、有效授权、适用输入边界和真实严重风险的防护。将通用清单改为适用条件、控制目的和经济可行的选择；不默认新增秘密服务、固定轮换周期、TLS-only/preload、特定基础镜像或扫描器。

同一 Skill 的直接示例不能反向恢复被删除的绝对要求。可删除误导性示例或缩成有前提的片段；不为保住示例而建设轮换框架、Flask 服务或 CI 系统。SQL 关键词过滤不能作为注入防线，字符串检测不能替代上下文编码；这类与错误硬门槛直接相连的内容按有效机制纠正。其他无关安全债务不进入本里程碑。

### C6. 审查与收尾承认合法取舍

review 双向检查遗漏主目标和过强承诺，也检查次要目标是否被错误提升为 gate、是否用 best effort 偷降必达结果。安全或 oracle 标签影响实际风险判断，不产生固定审查轮数或 evaluator 的修复权。

最终报告区分：主目标与请求终点是否完成、实际交付版本、次要能力取舍及原因/影响、执行过的验证和未验证部分。主目标和批准的验收范围满足时，可以使用既有 `pass`/`closed`；不能同时冒称所有 feature 完成。受影响生产动作尚未执行时如实报告该终点未完成。无需新增结果枚举或永久风险账本。

## D. 计划表达与渐进披露

计划保留当前有效目标、裁量、责任、交付终点和少数真实暂停条件。区分用户决策、可调查事实、待生成实施产物、技术验证与已批准适配，不把 required authority 全部写成 missing authority。

新的证据或局部取舍更新当前有效段落；有保留价值的历史修订留在阶段记录，通过短引用访问，不在每个任务重复所有旧 gate 的豁免。文档长度不是新 gate。本次仅修改通用写作指导，不迁移或清理 Drone/Homelab 或本仓库全部旧计划。

各 Skill 保留可独立使用所需的短规则；详细方法使用现有 reference 渐进披露，不强制加载 router、通用风险引擎或一份跨 Skill 运行时契约。稳定架构文档说明职责归属，不成为模型执行所需的新输入。

## E. Pi 会话挖掘的有界增量

在现有 stdlib Python CLI 中增加 `pi` source、重复/逗号分隔的 `--pi-home`（默认 `~/.pi/agent`），读取其 `sessions/**/*.jsonl`；默认 sources 加入 Pi，默认 repository scope 仍为 `current`，跨仓库仍需明确 `--scope all`。不读取该 home 的 auth、settings、数据库、其他运行时存储或子代理私有状态。

保留现有 source 选择、JSON/Markdown 结构与 Codex/Claude/Grok 语义；新增 `pi_homes`、Pi 计数/事件为兼容增量。支持已有 skill-usage 模式、日期截止和输出 opt-in，不因新增 Pi 而静默返回“零使用”。没有 Pi 文件是零观测，坏行/不支持格式或不完整分支则需可见地说明证据不完整，不能伪造完整计数。

以 Pi v3 JSONL 的 header `cwd`/`id`、entry `id`/`parentId` 和 message 类型为输入，按最后可确定的记录分支解释会话，并报告这个选择而非保证等于 UI 当前选择。不要把互斥分支拼接；保留 model change 与 assistant 实际 model 的差别。compaction/retainedTail 和 fork 复制前缀不得重复计入同一消息；跨 session 的复制/祖先关系无法可靠判明时披露限制，不输出虚假的唯一任务数。

计数区分 assistant `stop`、`toolUse`、`error`、`aborted`、`length` 与 compaction；普通 stop 不是任务完成、提前停止或需要批准的证据。可报告终结回复之后出现批准/继续提示的候选关系，但是否多余由调用方结合目标和权限裁决。新建议不得继续输出可执行审批 gate 或旧 reviewer 协议。

只把真实 user 的非注入文本当意图。剥离 `<skill ...>...</skill>` 后保留用户尾部请求；技能加载、assistant 引用和注入正文不是用户明确调用。Pi skill-usage 解析结构化工具名/路径，不递归摊平全部 payload。默认仅聚合；正数 `--limit` 才允许有界、脱敏文本样例，thinking、图片、原始工具参数/结果和秘密不成为报告正文。已有显式 include-output 可用于分析受限工具文本中的使用信号，但不解除报告的敏感内容边界。不声称文本脱敏可以保证任意敏感文本安全，也不把会话数据写回源文件或发布到外部。

扩展现有 scanner，不重写其他格式或建立宿主 adapter。新增测试使用合成临时 homes、闭合环境和假 session；不依赖真实历史、凭据、Pi 安装或模型调用。私有历史只提供本次设计动机，不复制为分发 fixture。

## F. 可复用行为场景

以下是指导审查与可选后续比较的正反案例，不是运行时规则表或每次工作的验收清单。实施时将通用版本放入 testing-strategy 的参考资料，复用既有 evaluation 方法；不冻结下列自然语言为单元测试。

| 案例 | 预期行为 | 不应发生 |
| --- | --- | --- |
| 主目标为可用的跨 core 适配，某次要 matcher 无法表达 | 有依据地标记 unsupported，验证剩余主路径并继续 | 要求先穷举全部降级清单或逐项重新批准 |
| 同一 matcher 被用户明确指定为必达，或承担主目标必要保护 | 保留要求，诊断；无可行路径时提出具体决定 | 事后改称次要目标、删除 oracle 后报全通过 |
| 已批准同目标部署，仅缺新 bundle digest/binding | 核实并生成，验证后继续 | 向用户索要尚未生成的技术材料 |
| 用户已回答唯一阻塞且原执行授权有效 | 同一任务恢复实施 | 只说“我会继续”后终结 |
| 已授权的可重建开发 schema 更新 | 按允许的重建路径验证和部署 | 因远端/Ansible 字样反复做完整还原演练 |
| 同环境实际连接生产密钥、共享服务或唯一数据 | 保护受影响边界并核实操作范围 | “开发”标签抹掉真实损失，或反向冻结所有无关工作 |
| 次要取舍使生产行为/风险超出已批准预期 | 本地安全工作继续，受影响生产动作前请求窄授权 | 先上线后披露，或重开全部设计 |
| 正常业务组存在，但不能各自独立选点；或 mirror/版本告警遗漏 | 用户场景指出缺陷，补实现和相应证据 | 用 parser/golden 通过代替用户目标 |
| 普通模板修复，数据库/恢复条件未变 | 复用仍有效恢复证据，运行相关检查 | 因新提交或复审再次重复恢复实验 |
| 实际恢复实现/需保留数据的迁移改变 | 重验受影响状态转换及恢复路径 | 以提速为由只做空库启动测试 |
| 用户指定库，局部 glue 尚未确定 | 实施者选择合理粘合方式 | 擅换指定库或要求用户设计每个函数 |
| 普通 Pi stop、网络错误、compaction、分支和“继续”相邻 | 分别统计并保留上下文限制 | 自动判定 premature stop、任务成功或模型优劣 |

## G. 验证、审查与恢复

文档/提示语义使用有界源码审查、上述正反场景及 prose/link 检查；不添加 Markdown 句子、关键词或标题含义断言。Pi scanner 用现有 CLI 测试验证真实输入/输出行为和兼容性。分发仍运行仓库既定生成与检查，保持 39 IDs 和 reference closure。

因本变更同时放宽执行裁量并保护真实生产/数据边界，设计和计划各做一次有界独立评估；调用方裁决，只有修复使关键证据失效或仍有独立问题时才定向复审，不设默认反复审查流程。实施候选也需要覆盖该双向边界的独立评估，不把每个 Skill 文件拆成独立 review gate。

不运行付费模型比较、真实部署或备份演练作为本里程碑条件。维护检查和场景审查不能证明实际减少人工轮次或更安全；需要效果证明时，另按已有 evaluation 方法固定任务/host/模型/权限，对比原始与候选提示，并同时统计目标完成、越权/漏项和不必要中断。

本仓库变更默认当前 checkout、保留无关修改并 fix-forward。生成差异从 authored source 修复；没有用户安装、Git history rewrite、自动回滚或外部清理动作。设计/计划的审查及验证结果统一记录在配套计划，不在本文复制逐轮历史。
