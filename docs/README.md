# Docs

This directory mixes long-lived reference notes with stage artifacts kept for history.

## Stable Truth

- `quickstart.md` is the new-user entry: install verification, entry-point selection, and a first end-to-end change walkthrough.
- `architecture/workflow-orchestration.md` is the canonical maintenance view of lifecycle routing, the installed invocation DAG, and implementation repair convergence.
- `architecture/generated/*.svg` are the rendered human-facing views (harness routing sequence, implementation DAG, repair loop, skill planes, activation and trigger ownership). They are tracked, generated by `scripts/generate-workflow-diagrams.py`, and must not be edited by hand.
- `architecture/diagrams/*.puml` are the generated PlantUML sources for those SVG views and must not be edited by hand.
- Other files under `architecture/` document focused mode, invocation, install-surface, and maintenance contracts.
- `changelog/design-decisions.md` records implemented decisions and recurring negative guardrails whose boundary, rationale, consequences, compatibility obligations, or reconsideration triggers retain future value. Proposals and one-time execution mechanics remain in stage history.

## Search Defaults

- Default docs searches should avoid `docs/plans/`.
- Search that directory only when you explicitly need history, evolution, or dispute resolution.
- In this repository today, use `rg --no-ignore -n "pattern" docs/plans` for historical search.
- Keep stage artifacts in Git for history; use search-ignore rules to keep them out of default project explanation flows.
- Do not archive or delete tracked stage artifacts by age, count, or completion quota. Transfer unique durable facts and repair links before compacting or retiring stable decision records.
- Repository-level archived material has its own `.ignore` boundary and is searched only with an explicit `rg --no-ignore archived` request.
